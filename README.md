# 前端 UI 快速还原套件 3.0

用于让 Cursor 快速从设计原稿还原 App / Web / H5 / 小程序 UI。3.0 以 `架构需求.md`、`资源导入清单.md`、`像素还原清单.md` 和 `AGENTS.md` 四类文档协同为核心：`架构需求.md` 管范围和真实能力边界，设计原稿命名负责生成屏幕清单，切图/资源命名负责驱动组件、弹窗、状态按钮和常规交互蓝图，并把假设写回清单和变更记录。

## 核心原则

- 默认只做 UI 和本地演示数据；真实 API、登录、支付、AI 等能力必须在 `架构需求.md` 明确后才能接入。
- 设计原稿只作参考，禁止进入运行时资源或源码路径。
- 规划阶段必须先完成全部可用切图/内容素材的扫描、命名、导入/暂存和 `资源导入清单.md` 登记；未完成不得开始页面搭建。
- 页面图像必须严格使用 `资源导入清单.md` 中已导入的项目切图或现有工程 Assets；不得自行绘制/生成替代图案、图标、插画、纹理、头像、贴纸或背景。
- 禁止使用外部图片 URL、图标包、图库素材、AI 生成图、下载素材或任意非 §2 路径文件，除非先更新 `架构需求.md` §2 并获得明确授权。
- 代码绘制只允许基础 UI 原语，如文字、纯色块、边框、分割线、阴影、圆角矩形、骨架占位和布局容器；缺少关键切图时必须登记并等待补资源或明确占位授权。
- 必须按阶段门禁一步一步执行：安装/读取 -> 屏幕清单 -> 资源导入整理 -> 组件/交互蓝图 -> P0 实现 -> P0 全量截图对比 -> P1 实现 -> P1 全量截图对比 -> P2 实现 -> P2 全量截图对比 -> 最终验收；不能跳阶段。
- 屏幕清单可由设计原稿文件名自动生成：优先级、页面/状态、类型、对应实现、入口/触发和备注都会先给出推断值，并同步写入 `像素还原清单.md` 的界面名称/状态。
- `像素验收通过` 必须同时具备工程证据和全量截图对比证据；未截图或未对比的页面只能标 `实现完成` / `待截图验收`。
- 严格按 P0 -> P1 -> P2 推进：P0 未完成全量截图对比和返修闭环，不得开始 P1；P1 未完成不得开始 P2，除非对应行明确延期或不可验收并记录批准原因。
- 命名可推断组件、弹窗、状态和交互；推断出的行为必须登记为 `已绑定 / 已绑定但受限 / 待确认 / 不可推断`。
- 自动判断交互时必须检查完整性：触发、前置条件、结果、状态同步、失败/取消路径、能力边界和证据。
- 输入类交互必须检查键盘避让：消息发送栏、评论栏、搜索框和表单输入区不能被系统键盘遮挡。
- 同类组件和交互按模式登记一次；重复按钮/卡片实例只在资源清单和像素证据中记录，不反复写进变更记录。
- 变更记录不是流水账：每条 §10 变更都要反查同步到能力边界、交互登记、资源清单、像素证据和 AGENTS。
- 低风险交互可直接实现：返回、关闭、Tab 切换、页内筛选、展开收起、点赞/收藏本地切换、举报/拉黑 sheet、删除确认、空态入口、设置页静态跳转等。
- 关注/好友等社交关系可做本地演示切换；涉及跨页面同步、数量变化或关系持久化时必须登记假设或待确认。
- 高风险能力不得凭命名越界：真实 Apple 登录、支付/IAP、WebView 外链、删除账号、媒体权限、AI/聊天扣费、后端 API 必须在 §6 明确真实程度。
- 长案例只放在 `案例-*` / `参考-*` 文件里，不作为默认模板。

## 安装

Cursor 只读取项目根目录的 `.cursor/rules/` 与 `.cursor/skills/`。套件放在子目录但未安装时，Skill 不会触发。

```bash
cd 前端UI开发套件3.0交互补全版（未实验）
chmod +x install-to-project.sh verify-kit-install.sh
./install-to-project.sh /path/to/ProjectRoot --init-project-docs
./verify-kit-install.sh /path/to/ProjectRoot
```

`--init-project-docs` 会生成项目根文档：

- `架构需求.md`
- `AGENTS.md`
- `像素还原清单.md`
- `资源导入清单.md`

在 Cursor 中：

```markdown
@架构需求.md

请先扫描设计原稿文件夹，按原稿命名自动生成/修正 §3 屏幕清单和像素清单；再根据切图/资源命名生成组件、弹窗、状态按钮和交互蓝图。
规划阶段必须先递归扫描 §2 可用切图/内容素材路径，将所有运行时可用资源导入或暂存到工程资源目录，并完整写入 `资源导入清单.md`；未完成不得开始页面搭建。
请先审计 §10 变更记录是否已同步到 §4.2/§4.3/§6、AGENTS 和两份清单；若还有模板占位先补齐。
请按交互完整性矩阵补齐 §4.2：触发、前置条件、结果、状态同步/失败路径、风险和绑定状态。
请重点检查消息发送栏/评论栏/搜索和表单输入在系统键盘弹出时不被遮挡，并把 keyboard 证据写入像素清单。
页面图像只能使用 `资源导入清单.md` 中已导入的 §2 可用切图或现有工程 Assets；不要使用外部图片 URL、图标包、图库素材、AI 生成图、下载素材或非 §2 路径文件，也不要自行绘制或生成替代图案、图标、插画、头像、贴纸、背景。缺图先登记为待补，除非我明确同意占位。
必须按阶段门禁执行：屏幕清单 -> 资源导入整理 -> 组件/交互蓝图 -> P0 实现 -> P0 全量截图对比 -> P1 实现 -> P1 全量截图对比 -> P2 实现 -> P2 全量截图对比 -> 最终验收，不可跳过某阶段直接进入下一步。
低风险和安全本地演示交互可直接实现，高风险能力先写为待确认。
每屏完成后更新 `资源导入清单.md`、`像素还原清单.md` 和 `架构需求.md` §10 变更记录。
每个页面、弹窗、空态、加载态、错误态和关键变体都必须截图，并与目标原稿做对比；没有截图和对比证据不得标 `像素验收通过`。
同类交互只登记一条模式；重复实例写入清单证据。
```

## 像素验收

`实现完成` 代表代码、切图、约束已落地。

`像素验收通过` 需要在 `像素还原清单.md` 同时记录工程证据和截图矩阵证据：

- 入口/路由
- 原稿文件和屏幕清单推断结果
- 界面名称/状态，与 `架构需求.md` §3 `页面/状态` 对齐
- 实现文件
- 布局/约束位置
- 已登记资源
- 3-6 个关键元素度量
- 命名推断出的组件/弹窗/状态控件
- 关键按钮交互：资源名、触发、结果、绑定状态
- 同类交互模式及本屏差异
- 截图状态、目标原稿、实现截图、对比证据、视口/设备
- 差异等级、返修状态
- 例外项或 `无例外`

截图是每个不同界面/状态的强制验收项。diff、并排对比或人工复核记录至少需要一种作为对比证据；随机抽检只允许用于已经有代表样例通过的重复组件实例，不能替代页面/状态级覆盖。

## Skill 生效标志

Agent 应该主动做到：

- 先做 P0/P1/P2 缺口审查。
- 扫描设计原稿文件名，自动生成/修正屏幕清单和像素清单初始行。
- 首轮运行时先回写 `资源导入清单.md`、`像素还原清单.md` 和 `架构需求.md` §3/§4.1/§4.2/§4.3；清单写入是编码前置条件，不是收尾步骤。
- 规划阶段先完成全量切图扫描、命名、导入/暂存和 `资源导入清单.md` 登记；没有完成资源门禁不得搭建页面。
- 按阶段门禁一步一步执行，不跳过屏幕清单、资源整理、交互蓝图、分优先级实现和截图矩阵验收阶段。
- P0/P1/P2 必须批次闭环：当前优先级所有非延期页面完成截图对比和返修闭环后，才能进入下一优先级。
- 像素清单初始行必须列出界面名称/状态；不能只列原稿文件或保留模板占位。
- 扫描切图/资源命名，输出组件/弹窗/状态/交互推断表。
- 对照 Sweeli/hdxc/qxxq/lygl/clsj 沉淀出的项目按钮操作模式，补齐常见导航、社交、聊天、搜索、阅读、直播、发布、充值、音视频、账号、通知清理、媒体预览、跨页面同步和设置按钮行为。
- 读取 §10 变更记录并反查落点，发现 §4.2/§4.3 或清单仍是模板占位时主动补齐。
- 按完整性矩阵审计交互，不把“有点击事件”误判为“交互完成”。
- 对输入页检查键盘弹出/收起、safe-area、短屏、空发送和列表底部遮挡。
- 严格使用项目提供的切图/Assets；缺图时登记待补，不自制替代图片。
- 拒绝外部图片 URL、图标包、图库素材、AI 生成图、下载素材和非 §2 路径文件。
- 将同类交互合并为可复用模式，避免每屏重复铺表。
- 将低风险和安全本地演示推断结果绑定到页面代码，并登记证据。
- 将中/高风险交互写入 `架构需求.md` 待确认，不擅自接真实能力。
- 拒绝把设计原稿作为运行时资源。
- 按屏更新 `资源导入清单.md` 和 `像素还原清单.md`。
- 没有工程证据或截图对比证据时不宣称 `像素验收通过`。
- 新需求先写回 `架构需求.md`，再改代码。
